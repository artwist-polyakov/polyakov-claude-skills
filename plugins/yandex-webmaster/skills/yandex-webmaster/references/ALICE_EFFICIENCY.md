# Alice efficiency / Share of Voice

Раздел Webmaster «Эффективность → Алиса (нейросетевой поиск)»: показывает долю
показов сайта в ответах Алисы (Share of Voice), список конкурентов в нише,
а также примеры запросов — где наш сайт присутствует и где отсутствует.

## Особенность: нет публичного API

В [каталоге ресурсов Webmaster API](https://yandex.ru/dev/webmaster/doc/ru/concepts/getting-started)
нет документированных методов для этих данных (проверено 3 сентября 2026 года).

Данные приходят **только при SSR-рендере** HTML-страницы:

```
https://webmaster.yandex.ru/site/{host_id}/efficiency/alice/
```

В HTML встроен `<script>window._initData = {...}</script>` — там лежит весь
объект `alice` целиком. Параметры query (`tab`, `tableType`, `onlyWithMySites`)
управляют только клиентским отображением — переключение вкладок не делает
дополнительных запросов. Поэтому **одного fetch'а достаточно**, дальше парсим
четыре среза локально. Загрузка выполняется через `urllib` стандартной библиотеки
Python. Встроенный JSON извлекается через `json.JSONDecoder.raw_decode`, без
ручного подсчёта скобок и преобразования строк.

## Авторизация

Через cookie `Session_id` обычной браузерной сессии Яндекса. См. установку
в [config/README.md](../config/README.md). OAuth-токен Webmaster для Alice
не подходит.

## Использование

```bash
# Короткая сводка (по умолчанию)
bash scripts/alice.sh --host metallik.ru

# Share of Voice — 12 недельных точек
bash scripts/alice.sh --host metallik.ru --action sov

# Топ сайтов в нише по версии Алисы
bash scripts/alice.sh --host metallik.ru --action competitors

# Запросы где наш сайт встречается в ответах
bash scripts/alice.sh --host metallik.ru --action with-site

# Запросы где наш сайт НЕ встречается (= упущенный спрос)
bash scripts/alice.sh --host metallik.ru --action without-site

# Принудительно перекачать страницу (минуя кеш)
bash scripts/alice.sh --host metallik.ru --action fetch
bash scripts/alice.sh --host metallik.ru --action sov --no-cache
```

Принимает либо `--host <domain>` (поиск по `cache/hosts.tsv`), либо
`--host-id <id>` (формат `https:metallik.ru:443`). Если используете `--host` —
сначала выполните `bash scripts/hosts.sh` хотя бы один раз, чтобы наполнился
hosts кеш.

## Кеш

Все действия (`sov`, `competitors`, `with-site`, `without-site`, `summary`)
используют один проверенный объект `alice`:

```
cache/host_<host_id>/alice/init.json
```

Корректный кеш моложе 24 часов используется без загрузки страницы Alice.
Если кеш отсутствует, устарел или повреждён, скрипт загружает страницу заново.
Для принудительного обновления добавь `--no-cache` или вызови `--action fetch`.

Прежний `init.json` заменяется только после успешной загрузки и проверки новых
данных. При ошибке обновления он остаётся на диске, но команда завершается с
ошибкой: старые данные не выдаются за результат успешного обновления.

Рядом сохраняется `raw.html` — последний **полностью полученный** HTML,
в том числе страница с ошибкой авторизации, капчей или изменившейся структурой.
Недокачанный ответ не заменяет прежний `raw.html`. История HTML не ведётся;
`raw.html` и `init.json` могут относиться к разным попыткам, если последняя
загрузка не дала корректных данных.

TSV-файлы (генерируются по запросу действия):
- `sov.tsv` — `date_from / date_to / share / share_pct`
- `competitors.tsv` — `rank / url`
- `with_site.tsv` — `query / rank / host / url / title`
- `without_site.tsv` — `query / rank / host / url / title`

## Структура `_initData.alice`

```jsonc
{
  "viewModel": { "tableType": "EXAMPLES", "onlyWithMySites": "ON" },
  "alertType": "TOP3",                       // тип бейджа
  "sov": [
    {
      "dateFrom": "2026-01-12",
      "dateTo":   "2026-01-18",
      "sharePercent": 0.6659699980555219      // доля 0..1
    }
    // ... 12 недельных точек, ~3 месяца
  ],
  "queries": {
    "GENERAL": [                              // топ-10 сайтов в нише
      { "url": "https://www.ivd.ru", "favicon": "..." }
    ],
    "EXAMPLES": {
      "hasOwnExamples": [                     // запросы где есть наш сайт
        {
          "query": "шибер это что",
          "urls": [
            {
              "url":   "https://metallik.ru/articles/...",
              "title": "Шибер для дымохода ...",
              "host":  "https://metallik.ru",
              "favicon": "..."
            }
          ]
        }
      ],
      "noOwnExamples": [ /* такая же форма */ ]
    }
  }
}
```

## Ошибки и диагностика

Сетевой тайм-аут — 30 секунд; допускается до 3 попыток всего. Повторы
применяются к временным сетевым ошибкам и HTTP 429, 500, 502, 503, 504.
Если сервер прислал `Retry-After`, скрипт учитывает задержку до 60 секунд;
большее ожидание завершает команду с ошибкой — повторить запрос нужно позже.

Ошибки авторизации, капча, ошибка сертификата и ошибка разбора HTML/JSON
не повторяются. Перенаправление на вход распознаётся без загрузки страницы входа.

| Симптом | Что проверить |
|---------|---------------|
| HTTP 401/403, `userIsAuth=false`, перенаправление на вход | Актуальность `Session_id` в `config/.env` |
| Капча | Открыть Вебмастер в браузере и пройти проверку, затем повторить команду |
| HTTP 429/5xx, ошибка сети или тайм-аут после всех попыток | Доступность Яндекса, соединение, прокси и DNS |
| Ошибка сертификата | Сертификаты и настройки соединения; проверку TLS не отключать |
| Нет `window._initData`, некорректный JSON или отсутствует объект `alice` | `raw.html`, правильность `host_id`, наличие данных для сайта и изменения страницы |

Для диагностики сравни сообщение в stderr с последним `raw.html`. Файл может
содержать данные аккаунта: не публикуй его целиком и не выводи cookie в отчёт.

## Ограничения

Это извлечение данных из HTML, а не публичный API. Изменение `window._initData`
или структуры `alice` может потребовать поправки парсера. Повторы запросов
не исправляют изменения страницы и не обходят капчу.

## Проверка без аккаунта

Из каталога навыка:

```bash
python3 -B -m unittest discover -s scripts/tests -p 'test_*.py'
```

Тесты проверяют кеш, повторы и разбор сохранённых примеров с подменой сетевых
ответов. Аккаунт Яндекса и настоящая cookie не нужны; эти проверки не подтверждают
совместимость с текущим HTML Вебмастера.
