# Баланс и счета

Источник: [официальная спецификация ZoomKit API 1.8.0](https://zoomkit.ru/docs/api-v1.yaml).

## Что доступно

### Баланс

`GET /billing/balance` возвращает:

- `balance` — остаток на балансе ZoomKit в рублях;
- `daily_tariff` — полный суточный расход;
- `days_left` — число полных суток или `null`, если суточных списаний нет.

Это баланс ZoomKit, а не остаток рекламного кабинета.

### Уже выставленные счета

`GET /billing/invoices` не принимает параметров и возвращает счета владельца ключа от новых к старым:

- `id`, `number`, `created_at`;
- `amount` — сумма без сбора;
- `pay_amount` — итоговая сумма к оплате;
- `status`: `wait`, `paid` или `cancelled`.

Параметры `--status` и `--limit` сценария фильтруют уже полученный список локально; в API таких параметров нет.

## Чего в API нет

В версии 1.8.0 отсутствуют методы для:

- создания или повторного выставления счёта;
- передачи либо выбора реквизитов плательщика;
- получения одного счёта по идентификатору;
- скачивания печатной формы;
- создания или получения ссылки на оплату;
- проведения оплаты.

Спецификация прямо говорит, что реквизиты плательщика и печатная форма доступны только в профиле. Поэтому произвольные реквизиты нельзя передать через API независимо от того, были ли счета раньше.

Если пользователь только спрашивает, можно ли выставить счёт или получить ссылку, ответь по этому ограничению без авторизации. Если ключ уже настроен или пользователь отдельно просит проверить свои счета, покажи ожидающие оплаты:

```sh
sh scripts/zoomkit.sh invoices --status wait
```

Затем направь в профиль: https://zoomkit.ru/profile. Не пробуй недокументированные адреса. Если возможности профиля недостаточно, предложи обратиться в поддержку: support@zoomkit.ru.

Оплата по публичной оферте производится безналично в рублях по предоплате; после оплаты сумма отражается на балансе ZoomKit. Пункт 4.7 оферты предусматривает добавление 6% к сумме пополнения на этапе оплаты, поэтому итог нужно проверить в профиле: https://zoomkit.ru/docs/offer.pdf
