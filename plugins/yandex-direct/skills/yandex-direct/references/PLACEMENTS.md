# Места показа кампании

Читайте перед созданием кампании, копированием её настроек или изменением мест
показа. Товарное объявление из фида определяет содержание рекламы, а места
показа задаются отдельно на уровне кампании. Само наличие `ShoppingAd` не
ограничивает рекламу товарной галереей.

## Сначала выберите охват

Исходите из задачи пользователя. Для проверки товарной галереи предлагайте
только галерею. Поисковую выдачу, РСЯ, Карты и другие места добавляйте, когда
для них есть задача и согласован расход. Если сказано лишь «товарная кампания»,
уточните, нужна ли только галерея или более широкий охват, и объясните разницу.
Уже известный выбор повторно не спрашивайте. Работающую кампанию не сужайте
автоматически: сначала прочитайте настройки и результаты.

| Место | Когда включать | Как задаётся в ЕПК |
|---|---|---|
| Товарная галерея | Карточки товаров на поиске | `Search.PlacementTypes.ProductGallery` |
| Поисковая выдача | Нужна также реклама в выдаче по запросам | `Search.PlacementTypes.SearchResults` |
| Динамические места на поиске | Нужен этот дополнительный охват поиска | `Search.PlacementTypes.DynamicPlaces`; ограничения ниже |
| РСЯ | Нужны показы в рекламной сети | Стратегия `Network`; `SERVING_OFF` выключает сетевую часть |
| Яндекс Карты | Важен локальный спрос и продвижение организации | `Maps` в обеих частях стратегии: `Search` и `Network` |
| Список организаций, отели и галерея услуг | Предложение подходит этим местам | API содержит `SearchOrganizationList`; полный переключатель проверяется в интерфейсе |

`Search` в API шире поисковой выдачи: сюда входит и товарная галерея. Поэтому
для галереи поисковая стратегия остаётся активной, а `SearchResults` можно
выключить. `Network.PlacementTypes.Maps=NO` выключает только Карты в сетевой
части, а не РСЯ. Для запрета всей сетевой части нужен `SERVING_OFF`.

Места показа не заменяют [категории автотаргетинга](AUTOTARGETING.md):
«узкие запросы» определяют подбор запросов, а не список мест. `ExcludedSites`
исключает отдельные сайты и приложения; это также другая настройка.

## Создание: явный список вместо пропущенных полей

У новой ЕПК с активной поисковой частью `campaign_write.py create` требует
явно задать четыре доступных поля `--placement`: `SearchResults`,
`ProductGallery`, `Maps`, `SearchOrganizationList`. Значения `YES` и `NO`
попадают в план. Не рассчитывайте, что пропущенное поле означает «выключено»:
документация не задаёт полного набора значений по умолчанию.

Пример плана **только для товарной галереи**:

```bash
uv run scripts/campaign_write.py create --account example \
  --name 'Товары — галерея' --start 2026-10-01 \
  --search-strategy WB_MAXIMUM_CLICKS --weekly-budget 3000 \
  --network-strategy SERVING_OFF \
  --placement ProductGallery=YES --placement SearchResults=NO \
  --placement Maps=NO --placement SearchOrganizationList=NO
```

Дата, стратегия и сумма здесь для примера. Подставьте согласованные настройки,
цели и счётчик по задаче; [бюджет](BUDGETS.md) не выводится из списка мест.
Без `--apply` команда только готовит план. `Maps` команда отправляет сразу в
обе части стратегии. После создания кампании и группы добавляйте объявление
по [инструкции для фидов](FEEDS.md).

Для «галерея + выдача» нужен `SearchResults=YES`: при создании это включает
также динамические места. Если они не нужны, объясните ограничение API и
завершите выбор в интерфейсе до запуска. Для РСЯ со стратегией
`Search=SERVING_OFF` поисковые места не работают, но при включении поиска
их нужно выбрать заново; сетевые места проверьте отдельно в интерфейсе.

## Изменение существующей кампании

Прочитайте свежую карточку:

```bash
uv run scripts/campaigns.py --account example --campaign 123 --no-cache --json
uv run scripts/campaign_write.py strategy --account example --campaign 123 \
  --placement ProductGallery=YES --placement SearchResults=NO \
  --placement Maps=NO --placement SearchOrganizationList=NO
```

Вторая команда меняет только названные места и сохраняет текущий тип стратегии,
бюджеты и цели. Пропущенные при изменении места сохраняются. Если сетевая часть
уже выключена, этого достаточно для подготовки «только галерея» с проверками
ниже. Если она активна, отдельно включите в план её отключение через
`--network-strategy SERVING_OFF`; одни поисковые флаги РСЯ не выключат.
Не переносите пример стратегии и бюджета из команды создания в работающую
кампанию ради изменения мест. Для пакетной стратегии используется другая
структура `PackageBiddingStrategy.Platforms`; эта команда её не меняет —
подготовьте настройку в интерфейсе, сохранив саму пакетную стратегию.

Покажите таблицу «место — было — станет», включая РСЯ и динамические места.
Непрочитанное значение обозначайте «не получено», а не `NO`. После записи
перечитайте карточку и сверяйте также стратегию, бюджет и цели.

## Что проверить перед запуском

- **Динамические места:** при создании API приравнивает их к `SearchResults`.
  Отдельную запись `DynamicPlaces` команда не принимает. Для обновления
  документация такого же правила не обещает: проверьте фактическое значение,
  а при несовпадении с задачей измените переключатель в интерфейсе.
- **Карты:** API принимает пару полей `Maps`, но документированное чтение
  возвращает только поисковую часть. Команда отмечает сетевую часть как
  непроверенную (`unchecked`). Успешная запись не подтверждает весь
  переключатель Карт: проверьте его в интерфейсе.
- **Список организаций:** API читает и пишет `SearchOrganizationList`, но
  название переключателя в интерфейсе включает ещё отели и галерею услуг.
  Проверьте весь переключатель, прежде чем обещать их отключение.
- **Другие места интерфейса**, например мессенджеры, нельзя считать отключёнными
  по отсутствию поля в API. Проверьте их в том же блоке настроек.

Откройте ссылку редактирования кампании → «Места показа» → ручной выбор.
Сверьте весь список с согласованной таблицей, сохраните нужные значения.
Дайте пользователю [ссылку на настройки](UI_MAP.md#ссылки-на-кабинет-и-кампанию),
если проверку завершает он. До этой проверки называйте ограничения прямо; не сообщайте
«осталась только галерея» на основании двух полей. Создание черновика,
модерация и запуск показов — отдельные действия.
