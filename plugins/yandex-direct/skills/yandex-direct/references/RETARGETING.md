# Сегменты Метрики и ретаргетинг

Существующий сегмент Метрики используется в Директе через условие ретаргетинга:

**Сегмент Метрики → условие Директа → корректировка ставок или нацеливание группы.**

`retargeting.py` находит доступные сегменты, читает условия Директа и создаёт
простое условие из одного сегмента. Сегмент в Метрике остаётся прежним; отдельное
создание сегмента в Яндекс Аудиториях не требуется.

## 1. Найти источник и существующее условие

Команды запускаются из каталога скилла. Примерные логин и ID заменяй фактическими.

```bash
python3 scripts/retargeting.py sources --account example --search 'Корзина'
python3 scripts/retargeting.py list --account example --search 'Корзина'
python3 scripts/retargeting.py list --account example --id 789 --no-cache
```

`sources` показывает только доступные сегменты Метрики. Цели для статистики
по-прежнему выбираются через `report.py --list-goals`; сегменты Яндекс Аудиторий
этой командой не выводятся. Если подходящее условие Директа уже существует,
прочитай его правила и используй его ID.

У команд чтения есть `--search СТРОКА` и `--no-cache`. У `list` можно повторять
`--id ID`. Общие параметры: `--account LOGIN`, `--env production|test_cabinet`,
`--json`. Проверяй доступность и состав условия, а не только совпадение имени.

## 2. Создать условие из сегмента

```bash
python3 scripts/retargeting.py create --account example \
  --segment 1234567890 --name 'Посетители корзины' \
  --description 'На основе существующего сегмента Метрики'
```

Без `--apply` команда читает свежие данные и показывает план. Для выполнения
того же действия добавь `--apply`; `--dry-run` явно включает проверку без записи.
Действует общий [порядок изменений](CHANGES.md): конкретное поручение пользователя
уже разрешает запись.

Создаётся `RetargetingList` типа `RETARGETING`: одно правило `ANY` с одним
сегментом. Период и условия отбора посетителей определяет исходный сегмент
Метрики. Команда не редактирует его и не создаёт сложные сочетания правил.
После создания возьми ID условия из проверенного результата команды.
Если название уже занято, команда покажет ID существующего условия и не создаст
дубликат. Прочитай его правила; при другом назначении задай новое название.
Если такое же простое правило сегмента уже существует под другим названием,
команда также остановится и покажет его ID и имя: используй существующее условие.
Директ не допускает повторного создания одинакового правила.

| Идентификатор | Для чего нужен |
|---|---|
| ID сегмента Метрики | `retargeting.py create --segment` |
| ID условия Директа (`RetargetingLists.Id`) | `bids.py --retargeting`, `ads_write.py --condition` |
| ID привязки к группе (`AudienceTargets.Id`) | `ads_write.py group targets delete/suspend/resume --target` |

В API корректировок ID условия называется `RetargetingConditionId`, в API
нацеливания — `RetargetingListId`. Оба поля ссылаются на одно условие Директа.

## 3. Применить как корректировку ставок

Сначала прочитай корректировки кампании и нужной группы. Затем выбери один
уровень назначения:

```bash
python3 scripts/bids.py modifier list --account example --campaign 123
python3 scripts/bids.py modifier list --account example --group 456

python3 scripts/bids.py modifier add --account example \
  --campaign 123 --retargeting 789=120
```

Для назначения группе замени `--campaign 123` на `--group 456`. Значение `120`
означает коэффициент 1,2: **+20%**, а `0` — **−100%**, то есть исключение аудитории.
Для записи добавь `--apply`.

Аудиторные корректировки группы **замещают весь набор аудиторных корректировок
кампании для этой группы**. Например, если на кампании заданы условия A и B,
а группе назначено только C, в этой группе будут действовать корректировки C;
A и B с уровня кампании не наследуются. Учитывай весь итоговый набор перед
созданием групповой корректировки.

Коэффициент существующей корректировки меняется через
`bids.py modifier set --modifier ID --value 120`. Снять её можно через
`bids.py modifier delete --modifier ID`; ноль не снимает корректировку.
Эффект корректировки зависит от стратегии кампании.

## 4. Применить как условие нацеливания

```bash
python3 scripts/ads_write.py group targets add --account example \
  --group 456 --condition 789
```

`--condition` можно повторять. Для записи добавь `--apply`. На Поиске условие
аудитории сочетается с фразами и автотаргетингом через **И**: пользователь должен
соответствовать обоим условиям. В РСЯ условия работают через **ИЛИ**: аудитория
может стать самостоятельным основанием для показа.

Нацеливание назначается группе. Прямого назначения условия всей кампании нет;
если задача касается нескольких групп, перечисли их и примени условие к каждой.
Условие с областью `FOR_ADJUSTMENTS_ONLY` для нацеливания не подходит.

После записи проверь ID группы, ID условия и созданную привязку. Для её снятия,
остановки и возобновления доступны `group targets delete`, `suspend`, `resume`
с `--target ID` привязки. Успешная привязка сама по себе не подтверждает начало
показов: учитывай состояние кампании, группы и доступность аудитории.
