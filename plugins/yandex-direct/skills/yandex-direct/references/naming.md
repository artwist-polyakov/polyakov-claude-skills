# Названия и UTM-разметка

Перед созданием объектов посмотрите, как уже названы кампании и группы и как размечены ссылки. Сохраните понятную пользователю схему. Если схемы нет, предложите формат ниже и покажите итоговое имя вместе с разметкой.

## Имя кампании

Рекомендуемый формат:

```text
(домен)_(регионы)_(описание-модификаторы)_(место-показа)
(example.ru)_(moscow-mo)_(propitka)_(poisk)
```

Четыре части разделяются подчёркиванием; внутри частей используются латинские буквы, цифры, точки и дефисы. Последняя часть — `poisk`, `seti` или `poisk-seti`. Дополнительные признаки можно включить в описание: `master`, `gallery`, `retarget`. Имя кампании в API ограничено 255 символами.

Регион и места показа в имени должны соответствовать настройкам. У ЕПК поиск отключается значением `Search.BiddingStrategyType = SERVING_OFF`, сети — таким же значением в `Network`. Само имя настройки не меняет.

Если `utm_campaign` содержит имя кампании, переименование включает две связанные правки: `Name` и разметку в `TrackingParams`. Покажите обе в сравнении. Новое имя создаст новый срез в аналитике; это нужно учитывать при сравнении периодов.

## Имя группы

Называйте группу по одному намерению пользователя: продукту, услуге или сегменту спроса. Подойдут `propitka-derevo`, «Пропитка для дерева» или принятый в кабинете формат. Длинное перечисление всех вариантов запросов точно описывает набор, но неудобно для просмотра списка.

Ещё один вариант — имя группы, повторяющее набор запросов, например `(carl zeiss|карл цейс) (тео 020б|teo 020b)`. Оно точно описывает содержание, но длинное и хуже подходит для поиска по списку. Это вариант **названия**, а не разрешение отправлять OR-запись как новую ключевую фразу через API.

Если группы уже последовательно названы по одной схеме, новые называются так же. Если пользователь выбрал свою схему, следуйте ей. По его просьбе её можно сохранить для кабинета в настройке `group_name_scheme`. Согласие на разовое имя не означает просьбу запомнить его как постоянный формат.

## Разметка ссылок

Для ЕПК общая разметка задаётся в `UnifiedCampaign.TrackingParams`. У группы есть `AdGroups.TrackingParams`; значение группы переопределяет значение кампании. Когда нужного поля на уровне кампании нет, используйте группу. Проверяйте оба уровня и метки внутри самих ссылок.

Предлагаемая схема:

```text
utm_source=ya&utm_medium=cpc&utm_term={keyword}&utm_campaign=ИМЯ_КАМПАНИИ&utm_content=ph:{keyword}|phid:{phrase_id}|m:{match_type}|mk:{matched_keyword}|pt:{position_type}|p:{position}|g:{gbid}|a:{ad_id}|ret:{retargeting_id}|c:{campaign_id}|reg:{region_name}|s:{source}
```

`ИМЯ_КАМПАНИИ` заменяется полным именем. Имя с `&`, `#`, `?`, `=`, `%` или пробелом нельзя подставлять в строку буквально: сначала согласуйте корректное представление. Поле параметров URL ограничено 1024 символами.

Значение `ya` учитывает описанное Яндексом сокращение `yandex` при клике. При переходе с прежней схемы объясните, какие фильтры аналитики потребуется обновить. Существующую разметку не меняйте попутно при правке текста объявления.

`utm_term` содержит ключевую фразу. Короткие ключи `utm_content`: `ph` — фраза, `phid` — её идентификатор, `m` — тип соответствия, `mk` — подобранная Директом фраза, `pt` — блок размещения, `p` — позиция в нём, `g` — группа, `a` — объявление, `ret` — условие нацеливания, `c` — кампания, `reg` — регион, `s` — площадка.

`{matched_keyword}` не содержит исходный поисковый запрос пользователя. Запрос доступен в поле `Query` отчёта по поисковым запросам. Все макросы и ограничения: [url_macros.md](url_macros.md).

## Как избежать ошибок

- Не добавляйте одни и те же UTM-ключи одновременно в ссылку и `TrackingParams`.
- При сборке полной ссылки учитывайте существующий `?`, параметры и фрагмент после `#`; новые параметры должны стоять перед фрагментом.
- Показывайте готовую разметку каждой кампании, а не шаблон с незаменённым именем.
- Для быстрых ссылок проверяйте адреса и наследуемую разметку вместе с основным объявлением.
- Пользователь может сохранить свою схему в `utm_scheme`. Если она содержит буквальное имя кампании, сохраняется шаблон с заполнителем `ИМЯ_КАМПАНИИ`, чтобы следующая кампания не получила чужое имя.

Переход всего кабинета на другую схему выполняйте отдельной задачей с перечнем затронутых объектов и сравнением до и после.
