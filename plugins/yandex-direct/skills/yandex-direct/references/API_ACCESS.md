# Подключение к API Директа

Для работы нужны OAuth-приложение, токен с доступом к Директу и одобренная заявка приложения на полный доступ к API. Открытого программного доступа у аккаунта и действующего токена недостаточно: ошибка `58` означает, что регистрация приложения в Директе не завершена.

Если конфигурация уже настроена, начните со штатной проверки подключения. Содержимое файла с токеном читать и выводить не нужно. Порядок настройки описан в [config/README.md](../config/README.md).

## Заявка

Откройте [«Мои заявки» в настройках API](https://direct.yandex.ru/registered/main.pl?cmd=apiCertificationRequestList), создайте заявку и выберите полный доступ. Заявка относится к приложению; каждому его пользователю отдельная заявка не нужна. Статус и замечания видны там же.

В заявке укажите реальные функции установленной версии: получение статистики, работу с кампаниями и объявлениями, управление ставками. Подбор слов через отдельный Wordstat API требует отдельного доступа; заявка Директа его не открывает.

Техническое описание: Python 3.11 или новее, JSON, стандартная библиотека Python. Основной адрес — `https://api.direct.yandex.com/json/v501/`; API Live v4 используется только для методов без подходящего аналога в v5. Скилл работает с настоящим кабинетом, поэтому пробный вызов записи также меняет настоящие данные.

## Что написать о программе

Краткое описание можно составить из текста ниже, заменив название и сведения о пользователях. Перечень методов сверьте с фактически доступными командами.

> Приложение помогает вести рекламу в Яндекс Директе по запросам пользователя. Оно выгружает статистику по выбранным целям, проверяет настройки и готовит изменения. Перед записью показывает объекты и значения «было → станет», использует разрешение пользователя на задачу, после записи перечитывает данные и показывает фактический результат. Токен хранится локально и не выводится. Финансовые операции не выполняются.

| Методы | Назначение | Частота |
|---|---|---|
| AgencyClients.get, Clients.get | Выбор кабинета, валюта и ограничения | При начале работы, затем из кэша |
| Dictionaries.get | Регионы, валюты, часовые пояса, ограничения | Не чаще раза в сутки |
| Changes.check, checkCampaigns, checkDictionaries | Обновление устаревшего кэша | По мере работы, с ограничением частоты |
| Campaigns.get, AdGroups.get, Ads.get, Keywords.get и связанные сервисы | Структура и настройки объектов | По задаче пользователя, постранично |
| Reports | Расходы, конверсии, запросы, места показа | По задаче пользователя; готовые результаты берутся из кэша |
| Campaigns.add/update, Ads.add/update, Keywords.add/update, KeywordBids.set и другие поддержанные команды записи | Разрешённые изменения | Только для названной задачи, пакетами допустимого размера |

Для приложения также опишите:

- последовательность изменения: чтение → подготовка → проверка ограничений → «было → станет» → запись в пределах разрешённой задачи → перечитывание и сверка;
- обработку общей ошибки и ошибок отдельных объектов; частичный успех показывается отдельно;
- повторы временно неудавшихся чтений с задержкой; запись автоматически не повторяется после неопределённого результата, чтобы не создать дубли;
- постраничное чтение по `LimitedBy`, соблюдение размеров пакетов и остатка баллов `Units`;
- ожидание отчётов с учётом `Retry-After`;
- хранение токена вне Git и отсутствие токенов, паролей и cookies в выводе и журнале.

Если форма требует спецификацию, оформите это описание документом и приложите к заявке. Если заявку вернули, исправьте названные замечания и отправьте её повторно.

Актуальные условия подключения: [документация API Директа](https://yandex.ru/dev/direct/doc/ru/).
